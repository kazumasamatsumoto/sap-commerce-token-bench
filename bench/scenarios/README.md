## 1 ストーリー

**1 ストーリー = S03 → S04 → S05 → S06 → S07**(「配送予定日」を、依頼書から実装、画面、テスト、レビューまで通す)。
`bench/run.sh story <回>` で、1 つの作業ツリーの中で順に回す(前の担当の結果を次の担当が引き継ぐ。本物の進め方と同じ)。
S01(設計)と S02(文書のレビュー)、S08(性能)、S09(障害)は、ストーリーとは別に「1 スプリントに何回あるか」を人が決めて積み上げる。

## 通し(E01)

E01 は S03〜S07 と同じ「お届け予定日」を、要望から 1 つの会話で回す(本会話がまとめ役になり、cs-pdm → cs-occ-liaison → cs-backend → cs-frontend → cs-qa → cs-auditor を順に呼ぶ)。
本物の進め方に近い形での担当ごとのトークン数を見るためのもの。S03〜S07 の合計とは混ぜず、並べて比べる。`bench/run.sh E01 <回>` で回す。

## バグ修正

B01〜B05 は、1 本ずつ `bench/run.sh B0x <回>` で回す。1 スプリントに何件あるかは人が決めて表に書く(Claude は決めない)。
依頼文は利用者や運用の担当からの報告の形にし、原因は書かない。各ファイルの「答え」の節は担当には渡らない(作業ツリーに bench/ を入れない)。
